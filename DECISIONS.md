# Decisions

| Date | Decision | AI contribution | Human contribution |
|---|---|---|---|
| 2026-10-28 | Data model is multi-text from day one (texts have IDs; annotations, footnotes, and passcodes belong to a text), but the UI is built for one text at a time. | Spotted the tension between SPEC's "multiple texts deferred" and its per-text passcodes and text management; recommended a schema that supports multiple texts from day one, since adding a text ID later would mean a migration. | Approved. |
| 2026-10-28 | Annotation ownership is tied to a browser token, not just the entered name. On joining, the browser gets a random token; each annotation stores it, and only that token (or the admin) can edit/delete it. Names are not reserved: anyone can join as any name, and duplicate display names are allowed. Clearing cookies or switching devices loses edit rights to past annotations. | Flagged that SPEC's name-keyed ownership lets anyone edit anyone's annotations by typing their name; proposed a browser token; laid out token-owns-annotations vs. token-claims-name and recommended the former. | Chose the browser token, and the token-owns-annotations option. |
| 2026-10-28 | Claude makes the judgment calls in this project and logs them here, rather than asking about each one. | | Set this: the goal is a working tool, and the meta-goal is seeing how well Claude builds to a front-loaded spec. |
| 2026-10-28 | Stack: FastAPI + stdlib sqlite3 on a Fly volume, one machine; Server-Sent Events for live updates; plain JS modules, no build step; texts uploaded as Markdown. | Proposed it: annotations are discrete records on immutable text, so "real-time" only needs change notification, not collaborative-editing machinery. | Approved. |
| 2026-10-28 | Annotations anchor by UTF-16 character offsets into each chapter's text content plus a stored quote, which the server re-checks on every write. Texts can't be replaced after upload. | Chose it: immutable text makes offsets permanently valid, so no fuzzy re-anchoring is needed; the quote check stops corrupt anchors from ever being saved. | |
| 2026-10-28 | Chapters are split at top-level `# ` headings; any text before the first heading becomes a "Front matter" chapter. | Chose it: works for any text, after a one-time Markdown cleanup of the source. | |
| 2026-10-28 | Live updates are content-free pings; clients refetch all of the text's annotations (debounced 300ms) and redraw the chapter. | Chose it over sending deltas: a little more data, but clients can't drift out of sync. | |
| 2026-10-28 | Passcodes are stored in plaintext and compared case-insensitively ("Equiano" = "equiano"). | Chose it: a shared class word the admin needs to see, not a secret. | |
| 2026-10-28 | **Spec variance:** admin login is password-only (`ADMIN_PASSWORD`), with no email. | SPEC says "email + password or similar"; with exactly one admin, an email adds nothing. | |
| 2026-10-28 | Vocab highlights may have an empty comment (shown as "(no comment)"); commentary must have text. | Chose it: a bare vocab highlight is itself the question "what does this mean?" | |
| 2026-10-28 | Overlapping highlights show both tints (split top/bottom); clicking an overlap opens every thread under it in the panel. | Chose it: overlaps never nest in the DOM, and no annotation is hidden by another. | |
| 2026-10-28 | Colors: vocab is a muted blue tint, commentary a muted amber tint; footnotes gray; structural markers dark ink. Body font Literata. | Chose it, aiming for "distinguishable at a glance but not loud." | |
| 2026-10-28 | Structural links are numbered I, II, III… within the anchor's chapter, in the order anchors appear in the text; numbers are computed, not stored. Links may cross chapters (the numeral's tooltip names the other chapter). | Chose it: an outline at the top of a chapter reads I, II, III in order; deleting a link renumbers the rest. | |
| 2026-10-28 | **Spec addition:** the anchor end of a structural link gets a faint "→ I" numeral in the right margin, and anchor text underlines on hover. SPEC only describes the destination's marker. | Added it: without it, anchors are invisible text you'd have to know to click. Anchor text still gets no highlight color. | |
| 2026-10-28 | Structural links have no comment or thread. The author or admin deletes one with a × that appears on hovering its numeral. | Chose it: SPEC gives links no comment, and they live entirely in the margin. | |
| 2026-10-28 | Footnote marker is a faint superscript number after the footnoted range; the note shows in the left margin, level with the marker, on hover, and stays on click. On narrow screens it appears as a bottom sheet. Footnotes have no threads. | Chose it, reading SPEC's "marker on the text, content in the left margin on click or hover." | |
| 2026-10-28 | On screens at least 1200px wide, opening the comment panel shifts the page left so the right margin (structural markers) stays visible and clickable. Below that, the panel overlays. | Found in browser testing that the panel covered the structural numerals; SPEC puts both on the right. | |
| 2026-10-28 | URLs in comments become links; nothing is embedded. | Chose it, per SPEC's "links only" for media. | |
| 2026-10-28 | Deep links: `/t/<slug>#<chapter>/a<id>` opens a chapter with that annotation's thread. Cross-chapter link jumps add a browser-history entry, so Back returns. | Chose it: cheap, and makes sharing a specific comment possible. | |
| 2026-10-28 | Re-joining from the same browser with a different name changes the name used for future annotations only; past annotations keep the name they were made under. | Chose it: names are snapshots, which keeps history honest. | |
| 2026-10-28 | Equiano's own footnotes ([A], [B]… in the Gutenberg text) are removed from the uploaded text and saved separately, to be loaded as footnote annotations in the left margin. Chapter summaries become italic blockquotes; headings are normalized to "Chapter I", "Chapter II"…. | Chose it: SPEC places the text's own apparatus in the left-margin footnote layer, and inline [A] markers would be clutter that can never be removed (texts can't change after upload). | |
